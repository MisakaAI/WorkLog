# WorkLog 前端 API 入口

本文是 Vue 前端协议的导航。工作台整体读取和保存，使用 `revision` 检查是否被其他客户端修改；日志按日期独立保存，使用 `version` 检查。日志和工作日历不属于工作台快照。

## API 路径

API 基础 URL 应包含前缀，例如 `/api` 或 `https://backend.example.com/api`。下表路径均相对于该基础 URL。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/healthz` | 检查认证与数据库可用性 |
| GET / PUT | `/dashboard` | 读取／原子保存工作台快照 |
| GET / PUT | `/categories` | 分类管理使用的集合接口 |
| GET | `/projects/export` | 导出已保存的项目 ZIP |
| POST | `/projects/import` | 导入项目 ZIP（仅后端模式） |
| GET | `/today` | 读取服务端业务时区中的今天日志 |
| GET | `/worklog/dates` | 查询有内容的日志日期；也支持可选日期范围 |
| GET / PUT | `/worklog/{date}` | 读取／保存指定日期日志 |

Vue 常规工作台修改使用快照，分类管理使用集合接口，项目导入／导出使用 ZIP 接口；不调用单任务／单待办资源接口。后端另外实现的项目、分类、任务、待办 REST 接口及 MCP 工具，
见[REST API](../../docs/REST_API.md)及 [MCP 客户端指南](../../docs/MCP.md)。

## 通用约定

- 成功状态为 `200`，普通请求和响应使用 JSON，没有 `{ "data": ... }` 包装。项目导入请求为 ZIP、成功响应为 JSON；导出成功响应为 ZIP，错误仍使用 JSON。
- 个人数据响应使用 `Cache-Control: private, no-store`。前端禁用缓存，远端模式不会读写浏览器业务缓存，也不会在后端失败时回退到本地模式。
- 日期使用严格合法的 `YYYY-MM-DD`。版本号为非负安全整数，成功写入后递增；达到上限后拒绝继续写入。
- 错误结构、状态码、项目 ZIP 格式和健康检查响应统一见 [REST API](../../docs/REST_API.md)。未保存的合法日志日期返回空日志资源，不是 `404`。

前端请求超时为 15 秒且不会自动重试写操作。超时可能发生在服务端提交之后，
应重新读取确认结果，不要盲目覆盖。所有数据按服务端解析出的可信身份隔离；请求体不能指定所有者。
删除／清空属于受控的破坏性操作，可能因当前认证渠道的权限策略返回 `403`。
部署配置见[部署与配置](../../docs/DEPLOYMENT.md)；认证、CORS、请求限制和完整权限策略见[身份认证与安全](../../docs/AUTHENTICATION.md)。

## 版本冲突处理

工作台写入必须基于最近读取到的 `revision`；日志写入必须基于该日期最近读取或保存成功的 `version`。
版本不匹配时服务端返回 `409 VERSION_CONFLICT`，且不修改已有数据。

客户端不会自动重放冲突草稿。工作台冲突后需刷新读取最新快照，再由用户重新应用修改；
日志冲突时先备份草稿，并在明确确认放弃草稿后重新读取。切换日志日期不会把草稿写到其他日期。
